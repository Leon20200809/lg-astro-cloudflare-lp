# LG Codex Kit｜DONEチェックリスト

Codex戦闘員が「任務完了」と報告する前に確認する共通チェックリスト。

目的は、**コードを書いたことではなく、任務が安全に完了したことを確認すること。**

---

## 1. 任務達成

- [ ] ACTIVE.md に書かれたGOALを満たしている
- [ ] 今回のMVP境界を越えて余計な機能を追加していない
- [ ] 指示されていない仕様を推測で追加していない
- [ ] 変更理由を日本語1文で説明できる

---

## 2. 既存機能

- [ ] 変更対象外の既存機能を壊していない
- [ ] 既存のURL・API・フォーム・データ形式を不用意に変更していない
- [ ] 既存class名・公開インターフェース・型を必要なく破壊していない
- [ ] 既存挙動を変更した場合、その理由を完了報告に明記している

---

## 3. 責務と構造

- [ ] 1ファイルの仕事を日本語1文で説明できる
- [ ] 実装コード・関数には、機能単位で必ず1行の日本語コメントを書いている
- [ ] 司令官スクリプトに細かい実装を詰め込んでいない
- [ ] 型が「部隊の納品規格」として機能している
- [ ] マジックナンバーや接続設定を実働処理へ散らしていない
- [ ] 再利用されていない処理を無理にhelper化していない
- [ ] 必要以上の抽象化・汎用化を追加していない

---

## 4. データと事実

- [ ] 取得した事実と推論結果を混同していない
- [ ] 不明な値を推測で埋めていない
- [ ] 外部データの変換結果を確認できる
- [ ] 型・JSON・APIレスポンスなどの完成形がGOALと一致している

---

## 5. 外部サービス

外部API・DB・クラウド・CLI・メール・ストレージ等を使用した場合のみ確認する。

- [ ] 接続できることを確認した
- [ ] 読み取りできることを確認した
- [ ] 必要な場合のみ書き込みを確認した
- [ ] 本処理より先に疎通確認を行った
- [ ] APIエラー時に原因をログから確認できる
- [ ] 本番環境とローカル環境の設定値の供給元を把握している

---

## 6. 秘密情報・セキュリティ

- [ ] APIキーをコードへ直接書いていない
- [ ] Secret / token / credential JSON をGit管理していない
- [ ] `.env` / `.dev.vars` 等が必要なら `.gitignore` 対象になっている
- [ ] 公開してよい設定値と秘密情報を分離している
- [ ] ユーザー入力を扱う場合、必要なvalidationを行っている
- [ ] エラー時に秘密情報をレスポンスへ露出していない

---

## 7. 動作確認

プロジェクトで利用可能なものだけ実行する。

- [ ] build成功
- [ ] test成功
- [ ] lint成功
- [ ] type check成功
- [ ] `git diff --check` 成功
- [ ] 実際の主要操作を1回以上確認した

利用できない検証項目は、無理に追加せず完了報告で「未実施」と理由を書く。

---

## 8. UI変更がある場合

- [ ] PC表示を確認した
- [ ] tablet表示を確認した
- [ ] smartphone表示を確認した
- [ ] 主要CTAが利用できる
- [ ] フォーム入力・送信が壊れていない
- [ ] 見た目のためだけに不必要なDOMを増やしていない
- [ ] アクセシビリティを不用意に悪化させていない

---

## 9. Git差分

- [ ] `git diff` で変更内容を確認した
- [ ] 任務と無関係なファイルを変更していない
- [ ] デバッグ用コード・console出力・仮データを残していない
- [ ] 一時ファイルや不要生成物をコミット対象にしていない
- [ ] 次の未知領域へ進む前にセーブ可能な状態になっている

---

## 10. README・ドキュメント

以下に該当する場合だけ更新する。

- [ ] 実行方法が変わった
- [ ] ディレクトリ構造が変わった
- [ ] 新しい環境変数が増えた
- [ ] 新しい外部サービスを導入した
- [ ] MVP境界が変わった
- [ ] 運用手順が変わった

不要な場合は、READMEを変更するためだけの変更を行わない。

---

# 任務完了判定

以下をすべて満たした時だけ「完了」とする。

```text
GOALを満たした
↓
既存機能を壊していない
↓
責務が説明できる
↓
必要な検証に合格した
↓
差分を確認した
↓
秘密情報を漏らしていない
↓
次の作業へ安全に進める
```

## LG流の完了条件

**「書けた」ではなく「動く・確認できる・戻せる」で完了。**

次の未知領域へ入る前に、現在地点を確実なセーブポイントにする。
